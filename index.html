Send an email

When a backend URL and API key are configured in Settings, this form sends through the API. Otherwise it stays in clearly labelled local demo mode.

Own SMTP infrastructure

For direct delivery, deploy a mail server such as Postfix on a server with outbound SMTP access. Configure a sending domain, reverse DNS, SPF, DKIM, DMARC, TLS, bounce handling and abuse limits.

Do not put SMTP passwords in this browser or commit them to GitHub. Configure secrets on the backend host. Some cloud hosts block outbound SMTP ports.
OTP engine · local demo

With a configured backend, OTP is emailed and verified server-side. Without a backend, you can use a browser-only demo code. Backend OTP requires an email address.

Production OTPs must be generated and verified server-side, stored only as a secure hash with expiry, rate-limited, single-use, and never returned to the client.
SMS gateway

The API and delivery tracking design can be owned by this project. Sending SMS to public mobile numbers requires a carrier agreement, SMS gateway connectivity, or a compliant GSM modem/SIM deployment.

Example request

X-API-Key: YOUR_SERVER_ISSUED_API_KEY
Content-Type: application/json

{
  "to": "person@example.com",
  "subject": "Welcome",
  "text": "Your account is ready."
}

The API key must be generated and validated server-side. Do not use a browser-generated token as real API authentication.
